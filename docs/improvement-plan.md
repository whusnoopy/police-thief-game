# 后续修复计划与验证记录

设备范围：iPad mini 7 及更大的平板，以及 1920×1080 或更大的电脑屏幕。

上一批编辑器、触屏和行动反馈修复已提交为 `248fada`。本批保持现有玩法规则，优先完善以下流程。

| 优先级 | 问题与影响 | 执行方案 | 验收条件 |
| --- | --- | --- | --- |
| P2 | 备份仅在异常时能导出，没有整库恢复入口，跨设备迁移不完整 | 地图库提供导出、导入；导入前校验文件，作为新条目合并，重复地图跳过，保留损坏条目原文 | 完整备份、单图备份、重复导入、编号冲突、损坏文件和保存失败均有回归验证；不覆盖已有地图 |
| P2 | 首次掷骰后的复杂地图寻路仍同步枚举大量绕路 | 对不改变取钱状态的行动使用最短路线搜索；预计算格子与占位信息；保留未取钱小偷所需的路径分支，移入 Worker 计算 | 与修复前的确定性场景结果比较，既有银行绕路测试通过；验证任务取消与旧结果隔离，并测量复杂场景耗时 |
| P2 | 从当前地图卡片继续编辑会重置撤销历史；损坏条目移除后提示残留 | 当前地图继续使用编辑中的对象；重新计算损坏状态提示 | 同图历史保留、其他地图历史隔离、提示随实际数据变化 |

执行状态：三项实现完成，130 项自动测试及生产构建通过。浏览器验证了正常备份导入、损坏原文保留、重复导入跳过和当前编辑地图保留；生产 Worker 实际完成小偷、警察两次计算，并完成银行取钱及回合切换。检查了 744×1133 与 1920×1080 视口，浏览器未记录错误。视口检查使用桌面 Chromium，不代表 iPad Safari 真机测试。

寻路验证使用修复前保存的 320 个确定性场景，对比可达目标、消耗、路径长度、行动类型、取钱及驾车状态和剩余步数，结果全部一致。场景包含两种信号相位、不同骰点、步行/驾车、警察/小偷及取钱状态。

同机 Node 首次寻路测量（8 名驾车角色、高架桥地图、骰点 6；硬件相关数据，不作为测试阈值）：

| 场景 | 修复前 | 修复后 |
| --- | --- | --- |
| 警察 | 307.9 ms | 9.2 ms |
| 已带钱小偷 | 264.5 ms | 5.1 ms |

未带钱小偷仍需要较多路径分支，因此另外增加 Worker，将等待与界面响应分开。Worker 不可用时仍可通过同步回退完成行动。

后续可考虑自动恢复对局进度。它需要持久化角色、车辆、动物、骰点及行动阶段，并校验恢复后的状态一致性，适合独立一批实现。

## 5.0.2 寻路测量（2026-11-06）

测量样例现采用四向坡道连接出生区与大面积桥面，并给银行和基地设置合法坡道入口。旧高架自由进出地面的样例不再适用于新版规则，因此不与上表直接比较。8 名驾车角色、骰点 6，本次环境测得：警察 8.8 ms、携款小偷 5.2 ms、未携款小偷 379.3 ms；结果依赖机器，不作为测试阈值。

未携款小偷仍需保留经过银行的路线分支，正式界面继续在 Worker 中计算。新增测试用实际线程执行正式 Worker，验证四向坡道、两个阵营和不同骰点的结果与同步实现一致。生产浏览器也完成实际 Worker、掷骰、上车、上下桥和银行取钱流程。

## 5.0.3 斜视原型验证（2026-11-06）

新增 11 项投影、坡道表面、桥面点击、排序、视图切换、行动确认与拖动防误点测试，全量 191 项通过。生产构建继续使用原 14 张主体 WebP，未引入新图片或改变寻路规则。

浏览器用真实 Worker 验证四向坡道的鼠标及触屏流程；175% 放大后点击银行、原生触屏滚动、鼠标拖动及预览中切回俯视再恢复均通过。生产产物用实际掷骰、上车、换手、上下桥与银行取钱验证，哈希 Worker 及图片加载正常，无页面脚本错误。

根据用户“游玩区域太小”的反馈，本版内改为整视口斜视布局，标题及行动说明进入左侧栏，缩放工具放入地图。检查 744×1133、1133×744、834×1112、1920×1080，地图视口分别为 732×1121、873×724、822×1100、1602×1060 像素；其中窄屏侧栏为可收起的抽屉。1920×1080 的地图宽度从约 679 增至 1602 像素，收起侧栏后为 1900 像素。画面保留等比例，100% 完整居中显示，全图不因窗口变矮而裁切；另外检查 1920×600，画面按高度适配。

侧栏收放、窗口变化、鼠标/触屏放大拖动、触屏落点后自动展开确认、切回俯视及返回编辑器均通过浏览器验证。样例包含连续山脉、前景建筑、银行中角色、动物和桥面空车。用户已确认移动基本正常；遮挡后观察选取和银行等建筑朝向列入后续阶段。当前仍仅桌面 Chromium 与触屏模拟，尚需 iPad Safari 真机操作验证。

后续同版反馈补充：100% 时可从地图周围空白或不可点击地块按住左键拖动，抓手/点选光标区分区域，“全图”复位。浏览器确认图外空白、不可点击建筑格均能平移；拖动不提交行动或改变选择，下一次正常点击仍可进入银行。自动验证补充右键、小幅抖动、取消及松手误点防护。

## 5.0.4 斜视素材验证（2026-11-06）

`5.0.3` 已由用户确认并冻结为 `58fe264` / `v5.0.3`。本批新增 18 项几何、显示方向、视口、角色选择与地面起伏回归测试，全量 209 项通过；验证 16 种桥面开口、四向坡道栏杆、前后排序、两类四向车辆、表面贴合和图形边界、建筑轴线、连续山脊、地图边缘、信号以及方向跨视图保留/重新开局重置。

浏览器完成包含四向鼠标/触屏上下桥与银行取钱的原流程，并检查包含 46 个样例的独立素材页。生产产物完成实际掷骰、上车、换手、坡道、银行取钱和哈希 Worker 加载。斜视人物/动物另有 4 张 384×384 透明 WebP，共约 98 KiB；俯视原图保留，建筑/桥梁/车辆直接绘制 SVG。

在 Linux / i5-13500H 主机、无头 Chromium、1920×1080 下，补充细节后，100 格建筑首次显示重建约 69.4 ms、再建约 60 ms，8411 个节点；100 格桥面约 7.9 / 6.4 ms，1290 个节点。该测量包括同步显示重建，不是寻路耗时，不作为硬阈值或 iPad 真机结论。

用户已认可建筑朝向、素材风格与角色/车身比例，按反馈增加屋瓦、窗门、柱子/徽记、车身/轮毂及桥栏细节，细线合并绘制。同时修复选中后其他角色无法改选的问题，增加重复点选取消与侧栏“取消选中”，保留骰点并清除旧预览，鼠标/触屏在两种视角下的实际点击流程均通过；遮挡后的轮廓与选择、设施入口显示继续留给 `5.0.5`。本版继续按反馈增加过街立杆灯及正确朝向、水面下沉与草坪薄厚，新增六项回归并在鼠标/触屏中检查地面点选、路线、草地步行与水面驾车、整回合相位更新及视角往返。同时修复触屏落点被浏览器吸附到附近车辆的问题，以原始轻触位置确定目标，补充触屏/触控笔回归并重新验证换人和取消。完整素材说明见 [斜视素材约定](isometric-art.md)。

矮窗口复查发现并修复了竖长变横宽时的观察中心漂移：浏览器会先夹紧旧滚动位置，现保存地图坐标中心后再适配新尺寸。回归覆盖 100% 全图和放大后平移，以及 1920×600、四个原定尺寸、侧栏收放、俯视恢复和返回编辑。

新增 7 项回归，全量 216 项测试及生产构建通过。检查建筑/路障的真实基底居中、相邻格未被完整遮住、设施人物与车辆的不同锚点及出入恢复、透明四角与软阴影、部分/完全遮挡、工地/栏杆空隙、前后排序、纯轮廓不实心填充、编号/携款/押送提示、键盘选择及悬停稳定。

真实 Chromium 的鼠标与触屏流程验证实际被遮挡主体点选、编号选择/取消、银行门口离开后恢复大小和携款、预览中往返视角及图片失败回退。使用实际 SVG 滤镜比较显示轮廓前后像素，确认改变限于遮挡区域、跟随源主体且完整遮挡时内部透明。独立检查页现有 50 个样例；图片数量保持 18 张。

Linux / i5-13500H、无头 Chromium、1920×1080 下，100 格建筑（无角色）首次重建约 119.6 ms、再次约 87.5 ms，8514 个节点；100 格桥面约 14.3 / 15.4 ms，1412 个节点。测量包含同步显示及真实几何读取，不是寻路或 iPad 真机结果。人物透明源形状各缓存一次，切换视图取消旧订阅；仍须在目标平板实测连续操作、清晰度和流畅度。

按用户后续反馈保留适度向后遮挡，建筑/路障基底居中，人物、车辆、动物和过街灯缩小约 14%。用户已确认本版改动无问题并授权冻结 `v5.0.5`，iPad Safari 完整真机验收继续留在集中回归阶段；20×20 和连续行动尚未实施。
