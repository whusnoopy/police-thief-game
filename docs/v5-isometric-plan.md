# 5.x 斜视棋盘实施计划

规划日期：2026-11-06；后续范围更新：2026-11-07。当前冻结版本：`5.0.5`。首个正式发布目标：`5.1.0`。

本文同时记录后续实施约定与各阶段状态。`5.0.0` 规划冻结为提交 `933f20d` / 标签 `v5.0.0`；`5.0.1` 数据基础冻结为提交 `16b8aa1` / 标签 `v5.0.1`；`5.0.2` 玩法接入冻结为提交 `2c1a7f4` / 标签 `v5.0.2`；用户验收后的 `5.0.3` 原型、布局及拖动冻结为提交 `58fe264` / 标签 `v5.0.3`。`5.0.4` 素材及交互冻结为提交 `98a4e30` / 标签 `v5.0.4`。`5.0.5` 已接入遮挡轮廓、入口显示和按最新反馈调整的建筑/角色比例，用户已确认验收并授权冻结；20×20 和连续行动详见 [后续显示与玩法扩展](v5-next-mechanics-plan.md)，仍为未实现规划。当前实际能力以阶段状态、`game-rules-implementation-memo.md` 和代码为准。每批完成后更新本文及根目录 `CHANGELOG.md`，不得把计划功能记成已完成。

## 目标与范围

- 地图编辑器和地图库缩略图继续使用 2D 俯视方格；游玩过程采用固定相机的斜视菱形棋盘。先在原型中确定具体俯角、格子宽高比和美术比例，不将“斜 45 度”直接等同于某个固定压缩比例。
- 当前冻结版仍为 10×10；`5.0.6` 计划新增 20×20，并按地图自身尺寸处理，旧图保持 10×10。四邻格移动和每格一个通行位置保持；桥下不允许通行，不加入桥上桥下同时占位、层间抓捕或多层寻路。
- 普通高架桥处于统一的高处；仅通过指定上下桥格与地面连接。
- 人物、有人车辆、动物以及需要辨认的空车被前景物体遮挡时，显示高亮轮廓。
- 银行、警察局等设施中的角色缩小显示在门口；驾车状态使用入口外的车辆停靠位置。
- 保留阵营权限、骰点、基础移动费用、押送关系及胜负规则；`5.0.7` 计划新增剩余点数连续行动及操作费用。当前上/下车、取钱、交付的自动事件和终止行为需届时显式迁移，不将新机制写成冻结版的已有能力。

本轮不包含自由旋转相机、完整 3D 物理、可行走山坡、建筑室内、多格建筑占地、任意层数高架或独立上下层道路。场景不绘制暗示桥下可通行的路线。

## 高架与上下桥规则

### 单格模型与四向坡道

普通高架保留 `OVERPASS`；新增四个上下桥地形，建议命名为 `OVERPASS_RAMP_N/E/S/W`。方向统一表示“从低端朝高端”，使用地图上的北、东、南、西，不使用屏幕斜向描述存档方向。

| 坡道方向 | 低端连接 | 高端连接 | 两侧 |
| --- | --- | --- | --- |
| N | 南侧地面 | 北侧普通高架 | 东、西封闭 |
| E | 西侧地面 | 东侧普通高架 | 北、南封闭 |
| S | 北侧地面 | 南侧普通高架 | 东、西封闭 |
| W | 东侧地面 | 西侧普通高架 | 北、南封闭 |

规划默认值：每个坡道占一格，双向通行，允许车辆上桥和下桥；首版只有直坡，不在坡道内部转弯、分叉，也不直接连接连续坡道。需要转弯或分叉时，在坡顶之后使用普通高架格实现。

坡道低端默认连接陆上可驾车格，包括道路、斑马线和按原有权限可驾车进入的设施；不直接连接河流、草地或障碍。斑马线仍须通过信号和方向检查。坡道高端必须连接普通高架。新增坡道与普通高架均仅允许车辆通行，进入每格沿用高架的 `0.25` 步；进入地面格时按该目标地块原有代价计费。

以上为本计划采用的实施默认值，后续调整应先在本文和版本记录中明确变更。

### 相邻格之间的通行

通行判断必须同时检查出发格与目标格的连接边，不能只检查目标格是否允许车辆进入。

| 相邻组合 | 连接条件 |
| --- | --- |
| 普通高架 ↔ 普通高架 | 同高处、共享边，按四邻格连接 |
| 普通高架 ↔ 地面 | 始终不连接，即使两格紧贴 |
| 普通高架 ↔ 坡道 | 仅在坡道高端连接 |
| 地面 ↔ 坡道 | 仅在坡道低端连接，并继续满足地面原有角色、驾车与信号规则 |
| 坡道 ↔ 坡道 | 首版不连接 |
| 任意斜角接触 | 不连接 |

规则顺序为边界及拓扑连通、角色/行驶状态/信号/占位限制、移动代价与现有事件。上述条件必须全部满足，不能因允许通过坡道而跳过原有限制。上下桥本身不自动上车、下车或结束回合。

几何连接判断集中为一个无 DOM 依赖的领域函数，由游戏寻路、开局地图路线校验及桥面连接显示共用。动物仍不能进入高架或坡道；检查其移动、设施附近生成和回场流程，避免任何流程绕过限制。后台 Worker 与同步回退使用同一套规则。

逻辑坐标继续采用 `{ r, c }`，不增加可独立占位的 `z` 或 `layer`。显示高度由地形推导：普通路面为 0，水面/草坪允许轻微的美术起伏，普通高架为统一桥面高度，坡道在高低端之间变化。坡道停留时角色锚定坡中位置；沿路径移动的表现按边端高度衔接，防止上桥时跳到错误表面。

### 编辑器和校验

- 新增“上下桥”画笔、四向方向选择及高低端箭头；电脑与触屏均有可见的方向控制。相邻地形可给方向建议，保存后的方向必须明确，不能每次渲染重新猜测。
- 俯视编辑器标记普通桥面和坡道；预览同时显示能连接和被封闭的边。
- 允许保存未完成的地图草稿；开始游戏前检查坡道的高低端接法、边界、关键路线及实际可用入口。无入口的高架区域提示原因；破坏出生点出口、取钱、返程或抓捕条件时阻止开局。
- 不自动覆盖地面、设施、山或相邻格以补造坡道；方向修改、放置、删除及拖绘均纳入撤销/重做。
- 对孤立桥面、桥面紧贴道路但不能通行、坡道放反和侧边贴路提供明确提示。

## 素材与连接组合

普通桥面使用四条边的连接掩码，共 16 种拓扑：孤立 1、端点 4、直线 2、转角 4、三岔 4、十字 1。有效坡道高端也算作桥面连接，邻近地面不算。

坡道只有 N/E/S/W 四种基础形态。桥面与坡道的方向由规则组合，无须为每种相邻道路、建筑、车辆状态单独制作整张图片。连接形状由程序控制，贴图负责质感；可组合桥面、桥沿、桥墩、阴影和栏杆。固定光源下不能直接旋转完整带阴影的贴图来冒充所有方向。

| 素材组 | 规划范围 | 验收重点 |
| --- | --- | --- |
| 地面 | 草地、道路、河流、河岸、斑马线、格线和功能标记 | 连续拼接、投影一致、信号含义不变 |
| 高架 | 16 种连接形态或等价的程序拼接、四向坡道、栏杆与支撑 | 封闭边明显、高低端准确、桥面角色不被前后栏杆错误覆盖 |
| 静态主体 | 银行、警察局、基地、农场、普通建筑、工地、路障、山 | 统一视角、光照、落脚点和遮挡轮廓；山脉可组合 |
| 动态主体 | 警察、小偷、两类车辆、猪、牛 | 统一比例，车辆四向可辨；原型允许先复用旧图 |
| 独立提示 | 编号、阵营、携款、押送、路径、轮廓 | 小尺寸清晰；不烘焙到主体素材中 |

素材记录实际占地、落脚点、显示尺寸、遮挡轮廓和设施入口锚点。即使图像跨越相邻格，逻辑占地仍为原有一格。优先用现有素材验证投影；正式替换按照建筑、桥梁、角色与载具等批次接入，保留资源失败时的可辨认回退。

## 游戏渲染和遮挡

新增独立斜视游戏渲染器；现有俯视棋盘继续服务编辑器、地图库。游戏控制器向渲染器提供地图、角色、可达格、路径和选中状态，避免将规则继续绑定到某个方格 DOM 的子元素结构。

统一实现地图坐标到画面坐标及反向点击定位，处理平移、缩放、桥面偏移和坡道表面。纯地面的逆投影不足以决定桥面点击目标，需要按实际表面形状与可达状态判定。装饰图片不得抢走相邻格的点击；遮挡轮廓可代理到原角色选择，触屏继续支持预览与确认。

绘制顺序采用静态地面、按前后关系交错的场景物体与角色、必要的遮挡轮廓和界面提示。普通单格物体以落脚点深度排序，通常可以从行列和计算；跨格山脉、桥面、桥墩和前后栏杆需拆分并补充遮挡关系。不能简单将所有高架、所有角色或所有建筑各自作为一整层放到最前面。

### 建筑降低（5.0.5 新增范围）

银行、警察局、基地、农场、普通建筑、工地及路障保持当前风格，基底居中并适度降高。按用户最新约束，允许局部向后遮挡，但不能将其他格子完全盖住；不要求素材严格收在本格菱形内。人物、车辆、动物及过街立杆灯略缩小；门口锚点、阴影、轮廓及点击同步调整。山、草、水、高架及坡道不随建筑改低。详细验收见 [后续扩展计划](v5-next-mechanics-plan.md)。轮廓仍须覆盖山和桥等造成的部分/完全遮挡。

### 高亮轮廓

- 对人物、有人车辆、动物和空车使用实际主体透明形状生成轮廓；仅在被前景遮挡的部分将轮廓叠到遮挡物之上，可见部分保留正常深度关系。
- 部分遮挡和完全遮挡均可辨认；先按包围范围筛选，再使用遮挡轮廓/透明遮罩确认，不能把透明图片四角当作实心墙。
- 阵营色配合有对比度的描边区分警察、小偷、动物与空车；选中状态再增强。编号、携款、押送等必要信息保持可读，重叠时避免标签相互覆盖。
- 轮廓只表达已有实体，不改变占位、通行、抓捕与角色状态；已逃脱、被关押、被押送而不单独绘制的小偷不额外出现轮廓。
- 角色选择或可达落点被遮挡时仍须能够操作；落点使用清晰的地面/桥面指示及路径提示，不以整个建筑透明替代本轮约定的角色轮廓效果。
- 缓存素材轮廓和静态场景信息；移动、选中或视图变化时更新，避免为每个对象持续做完整图片像素扫描。

## 设施门口显示

采用“到达设施格后，将角色缩小显示在门口”的方式。缩小只是显示投影，逻辑位置仍是设施所在格。

- 银行、警察局、基地等分别配置门口锚点及角色缩放；缩放只作用于主体，编号与状态标记保持可读。
- 为驾车角色配置入口外的车道/停靠锚点，车辆不缩成能驶进小门的大小。银行不因门口显示触发下车；警察局与基地仍执行现有回库、交付、逃脱规则。
- 门口显示不新增“只能从门前进入”的通行限制；原本允许从哪些相邻格进入，仍由原规则决定。
- 离开设施恢复正常大小，角色仍占原设施格，不把占位转移到门前相邻道路；路径提示和点击归属保持一致。
- 对经过设施与最终停留分别验证，避免连续经过时大小闪变。到达时已执行逃脱、关押等状态转换的角色按现有状态显示或移除，不人为增加停留回合。
- 先适配银行、警察局、基地，再检查农场及停车设施的专用锚点；动物生成、回场和停车事件不因美术锚点改变。

## 旧地图与编码兼容

游戏版本 `5.x`、地图编码版本以及备份容器版本分别管理。现有内部地图模型标记与 `v3.` 分享编码也不是同一个版本号，不能全局替换数字。

由于普通 `OVERPASS` 的通行含义改变，新规则地图计划采用新的 `v4.` 地图编码，明确表示坡道约束。继续读取现有 `v3.`、`v2.` 及 legacy 数据，保留原始编码及来源；为新坡道分配稳定、显式的新地形代码，不挪用已有地形代码。备份容器在结构无需变化时保持原版本。

- 旧地图无高架时，可创建采用新编码的升级副本，地形、设施、出生点、取钱与逃脱路线保持原样。
- 旧地图含高架时，先显示原来的高架—地面接触边及需要检查的入口。在 2D 编辑器中为升级副本补坡道并重新校验；普通桥面不因旧地图来源获得侧边上下桥的例外。
- 不保证含旧高架的地图能无损自动转换：单格桥、多个侧向入口及边界桥面可能没有容纳坡道的空间。遇到这些情况保留原图，明确列出待调整位置，不能静默插格、覆盖设施或删除路线。
- 查看、导入与预览不覆盖原条目；升级副本按新记录保存，并保留来源关联和升级状态。未处理的旧高架图可继续查看和编辑；进入新版游戏前须完成升级和校验，不能读取后直接按新规则悄悄开局。
- “待升级/升级中”状态必须跨自动保存、重新载入、导出和导入保留。当前存储会规范化地图编码，因此需同时检查解码、规范化、存储恢复和备份路径，不能只修改编码器。
- 新地图回到旧程序时，应作为不支持的新格式处理并保留原文，不伪装成旧 `v3.` 导致错误规则或数据丢失。

兼容验收包含多次读写、重复导入、条目去重、升级副本编号、保存失败、损坏原文保留，以及未完成升级状态不会丢失。具体模型字段在数据阶段确定并由往返测试固定。

### 5.0.1 实施边界（历史记录）

- 新规则地图的存储记录标为 `schemaVersion: 4`；原地图库键及备份容器版本保持不变。旧规则规范化仍写 `v3.`，必要时在记录的 `originalEncodedMap` 中保留规范化前的编码。
- 普通编辑、清空、撤销和保存均保留规则集及升级来源；新规则首次写入旧规则条目时自动另建副本，避免覆盖原图。
- 本版提供俯视显示和数据接口，坡道不出现在现有画笔列表，升级流程没有正式 UI 入口。新规则地图可导入和查看，但开局校验及会话创建明确拒绝游玩，待 `5.0.2` 统一接入寻路与路线校验后开放。
- 自动验证覆盖 20 项新增场景，包括方向、连接组合、历史编码、升级状态往返、副本保护、损坏数据、存储失败恢复及开局门禁。本版尚不需要用户确认新视觉或做真机验收。

## 正式发布门槛

### 规则与数据

- 四向坡道的双向合法移动、侧边禁止连接、桥与地面紧贴但不连通、斜角接触、边界和坡道放反均有有意义的测试；普通桥转角、三岔、十字不受影响。
- 高架与坡道不允许步行/动物进入，成本正确；上下桥与信号、抓捕、携款、押送、停车和终止行动组合符合约定。
- 寻路、开局路线校验、Worker 与同步回退使用一致拓扑；取消计算、地图切换与缓存失效不会采用旧连接结果。
- 对明确保留旧行动规则的地图，无高架场景沿用既有行为；采用连续行动的新规则地图按新机制单独验收。桥面—地面边界场景按坡道规则重建，说明预期差异，不通过删除边界覆盖让测试通过。
- 新旧编码、来源与升级状态往返正确；升级副本不覆盖原图；备份导入和保存失败恢复可靠。

- 10×10 与 20×20 尺寸/坐标/索引不混读，旧编码和升级副本保留；扩展后编辑、撤销、预览、导入、保存及分享均可往返。
- 连续行动的预算、操作费用及主动结束一致，Worker/缓存不会采用前一段结果；信号/动物在完整回合结束时只执行一次。旧行动规则和新机制不因载入被静默互换。

### 显示与操作

- 覆盖全部桥面连接形态、四向坡道、连续山脉、跨格遮挡、地图四角、设施门口、车辆四向、角色状态和资源加载失败。
- 遮挡轮廓与实际前景重叠一致；不将完整角色实心绘到建筑前，也不错误显示已退出场景的角色。
- 可达格、路径序号、车辆所在表面、角色编号与状态在斜视画面仍能看懂；画面尺寸变化与缩放后点击仍准确。
- 鼠标操作、触屏预览/确认、分段续行/结束、地图切换、返回编辑和重新开局全流程可用；20×20 默认局部视野保证单格可读可点，全图仅用于总览。
- 建筑和路障基底居中，允许适度向后遮挡，但不能完全盖住其他格子；屋顶装饰和工地支架纳入实际轮廓验收。角色、车辆和灯具略缩小；山、草、水、桥保持高度约定。
- 按 744×1133、1133×744、834×1112、1920×1080 验证布局；格子变扁后若触控不足，以放大/平移改善，不通过压缩到无法点选来容纳全图。
- 在 iPad Safari 真机检查点击、缩放/平移、轮廓清晰度、加载和连续回合；桌面模拟尺寸不能替代真机结果。
