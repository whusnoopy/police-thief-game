# 绘本棋盘视觉升级评估

用户选择：清爽的绘本棋盘，柔和色彩、俯视地形、可爱角色。设备范围保持 iPad mini 7 / iPad Air 3 和 1920×1080 及以上电脑。

## 结论

推荐「代码生成地形边缘 + 绘本风格透明主体素材 + 独立规则提示」的混合方案。保留当前 10×10 地图和 DOM 交互结构，优先改造共享棋盘渲染层。当前体量没有引入游戏引擎或改用 WebGL 的必要依据。

生成图片适合统一建筑、人物、车辆、动物的画风；道路连接、河岸拐角和信号方向必须由地图数据精确决定。完整地图插画无法适应自由编辑；单纯把 emoji 换成图片也不会自动解决拼接。

## 当前实现的问题

| 位置 | 当前表现 | 应调整的原因 |
| --- | --- | --- |
| `src/styles/board.css` | 格间固定 `gap: 2px`，每格单独铺底色和背景 | 道路和河流被缝隙切断；重复的水纹、山纹强化了方块感 |
| `src/domain/map/cellDisplay.js` | 根据当前格输出一个主地块和一个 emoji，不读取邻格 | 无法选择直路、转角、路口或连续河岸 |
| `src/ui/game/unitRenderer.js` | 人、车、钱、押送状态组合成字符串，放在 80% / 88% 大小的白色牌子里 | 基础地块容易被挡住；状态改变时整体形状和宽度跳变 |
| `src/ui/board/boardRenderer.js` | 编辑、游戏、地图库共用渲染入口 | 是统一素材的良好切入点，但需要分别处理正式棋盘与微缩图的细节密度 |
| `src/features/editorController.js` | 局部编辑只刷新被更改格 | 加入邻格衔接后，还必须刷新相邻区域及撤销、重做涉及区域 |
| `.cell.path-hover` | 直接覆盖 `background-image` | 素材接入后会覆盖地形纹理，路径提示应独立叠加 |

此外，emoji 的具体外观受平台字体和绘制实现影响；自带素材可以统一 iPad 和 Windows 的角色轮廓、比例和光线。参见 [Unicode Emoji 显示规范](https://www.unicode.org/reports/tr51/#Display)。

## 推荐的画面分层

从底到顶依次为：

1. 连续地形：低对比草地、浅灰米色道路、蓝绿色河流；同类地块边缘无缝。
2. 接壤边缘：草沿、河岸、路沿和内外转角；不同规则的地形保持可识别边界。
3. 静态主体：银行、警察局、基地、农场、山和障碍。足迹以一格为限。
4. 动态主体：角色、车辆、动物；脚底或车底锚定当前格，缩小圆牌底座。
5. 规则提示：淡格线、角色编号、携款、押送、信号、可达范围、路径序号。文字和小图标由代码绘制，避免烘焙到图片中。

地图模型已经分开保存 terrain、features、spawns；可直接增加显示投影，无需修改 v3 分享编码或已有地图存档。素材名称、纹理变体、绘制方向属于显示层，不应写入行动规则。

## 地块自然衔接的实现

- 道路先读取上下左右的同类邻格，得到 4 位连接掩码（16 种组合，包含孤立、端点、直线、转角、三岔和十字）。铺装区域应能处理宽道路与广场，不能强行把每格画成狭窄公路。
- 河流、草地接壤再读取斜向邻格处理内角；正式素材可采用 47 种有效轮廓的 Blob 自动拼接，或者由 SVG 遮罩生成相同轮廓。两类地形完整的边角组合不能简单等同于 16 张图片。
- 没有网格缝隙；格线在最上层以细线叠加。编辑时增强，游戏时减淡。地块中心的点击区域仍是完整正方形，圆角仅是边缘装饰。
- 一次编辑更新被修改格周围的 3×3 区域；批量操作先合并坐标再更新。山的多格联动也要纳入。
- 草纹、水纹变体按地图坐标确定，刷新和掷骰时不随机重排。光照统一；带方向阴影的建筑不能随意旋转复用。
- 邻接规则必须匹配现有语义：银行等设施有 ROAD 底层；斑马线保留原方向；高架桥目前没有独立上下层，也不应通过画面制造不存在的交叉通道。

这是成熟的地形拼接思路。Tiled 文档区分边、角以及混合地形集，并介绍 47 格 Blob 集与修改时更新邻格：[Using Terrains](https://doc.mapeditor.org/de/stable/manual/terrain/)。本项目可借鉴其规则，不必引入 Tiled 或迁移地图格式。

## 素材制作范围

| 类别 | 制作方式 | 重点 |
| --- | --- | --- |
| 警察、小偷 | 独立透明 PNG 主体，后续制作发布尺寸 | 大轮廓、少细节；蓝色帽徽和红帽条纹形成双重区分 |
| 警车、普通车 | 两个基础素材，状态额外叠加 | 不把驾驶者、携款和押送组合成大量状态贴图 |
| 猪、牛 | 两个透明素材 | 同风格、低细节，不能与角色的队伍标记混淆 |
| 银行、警察局、基地、农场、普通建筑、工地、路障、山 | 逐个生成、统一比例与光照 | 可通行设施和完全阻挡物要有不同的轮廓语言；避免装饰侵入邻格 |
| 草地、路面、水面、高架桥面 | 先用低对比程序纹理，必要时补生成纹理 | 拼接边缘由程序控制；生成纹理须检查平铺接缝 |
| 井盖、P 标、斑马线、信号、状态角标 | CSS / SVG / 文字 | 准确、清晰、随状态变化，缩小后仍可读 |

当前生成的是警察、小偷、银行三张候选素材，均为 1254×1254 PNG，具有透明背景。原图合计约 3.31 MB，适合评估；正式版本应导出符合实际显示大小的资源，并在保留透明边缘的条件下优化体积。不能把所有全尺寸原图直接作为上线资源。

生成图的透明边缘、主体占比和视角仍需按真实格子复核。角色的通行规则和表情无关，携款与押送信息也不能依赖生成图中的微小装饰。

## 本次可操作样板

- 入口：`experiments/storybook/index.html`。运行 `npm run dev` 后打开 `/experiments/storybook/`。
- 绘本素材 / 现有符号切换，使用相同地图数据比较；符号视图用于结构比较，不是正式界面的逐像素复制。
- 草地、道路、河流相邻衔接；点击空格试画；可关闭格线检查接缝。
- 银行、警察、小偷使用本次生成素材。停车场、井盖、基地仍是规则标记；其余主体未在此样板覆盖。
- 小偷 4 点可达格直接调用现有 `calculateReachableActions`，没有另写一套可达规则。
- 只在内存中操作独立示例，未连接游戏地图库；不会写入玩家地图。
- 素材与完整生成提示保存在 `experiments/storybook/assets/`，使用内置 image_gen 工具。

样板展示美术方向和邻格衔接，不包含完整正式皮肤、回合操作、车辆/动物状态、全部地块或发布资源优化。Vite 默认生产入口保持原游戏；此实验页面不会被默认构建打包发布。

## 接入顺序与验收

1. 地形显示投影：先完成邻格掩码、无缝底层和格线覆盖。验收孤立格、拐角、十字、2×2 广场、内角、单格岛、对角接触、地图边缘。
2. 三张样板素材接入共享渲染器，并处理 palette、放置预览、地图库缩略图；补齐其余主体。
3. 独立状态与路径层：保证银行上有人、人物开车、携款、押送、动物和停车点叠加时仍能看懂；资源失败时保留文字或符号回退。
4. 编辑与回合回归：拖绘、山联动、撤销重做、重新开局和地图切换均正确更新邻格。检查可达集合、骰点和分享编码不变。
5. 按 744×1133、1133×744、834×1112、1920×1080 验证交互和缩小辨识度；最后做 iPad Safari 真机检查。图片原图大不等于棋盘中的可读性好。

本次验证完成：三张图片均加载成功，PNG 角落 alpha 为 0；浏览器验证了点画、邻格重绘、恢复地图、外观切换及 4 点可达提示（示例为 21 格）。绘本与符号视图切换后地图修改和可达提示保持一致。检查 744×1133、1133×744、834×1112、1920×1080 视口无横向溢出，棋盘尺寸分别为 600、460、600、576 像素，完整棋盘可见。浏览器未记录错误。JS 语法检查和原游戏生产构建通过；未做 iPad Safari 真机测试。
