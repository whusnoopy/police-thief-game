# police-thief-game

警察抓小偷地图编辑与棋盘游戏。

目标设备为 iPad mini 7 及更大的平板，常用 iPad Air 3，以及 1920×1080 或更大的电脑屏幕；不针对手机小屏幕优化。

开始游戏前会检查出生点出口、取钱与逃脱路线，以及多次抓捕需要的警察局。动物会定期回农场，避免永久堵路。浏览器存储失败时可以继续编辑，页面会提示尚未保存，并提供备份导出与重试保存。

编辑器支持鼠标左键、手指和触控笔拖绘，以及按一次拖绘撤销/重做（当前页面最多 50 次，切换地图后重置）。游戏提供行动结果、角色状态计数和车辆去向说明；平板点击落点后先预览再确认，电脑鼠标仍可直接点击移动。

地图库可导出全部地图或单张地图，也可导入备份 JSON（最多 5 MB）。导入会跳过重复内容、为冲突编号分配新编号，保留已有地图和当前编辑状态；损坏条目以原文保留。复杂路线在后台计算，计算期间仍可查看规则或返回编辑器。

山可以相邻组成山脉：新增山保留已有邻山，其余上下左右邻格自动铺草地，斜角不额外限制。草地缓冲可扩建为山；仍邻山的格子不能改成道路或设施。放置不会覆盖设施和出生点，拖绘山脉可整体撤销。

## 5.x 版本规划

当前版本为 `5.0.5` 测试版，游戏中可切换“俯视”和“斜视（测试）”，对局、选中角色和待确认路线保持不变。斜视采用已验收的 2:1 菱形格，并接入统一朝向的建筑、连续山脉、拼接桥面、四向坡道与车辆；汽车和警车朝向跟随行动最后一步，车身贴合所在桥面或坡面。人物和动物沿用绘本形象，斜视使用更清晰的 384 像素透明素材及统一比例与落脚点。 本版细化了屋瓦、门窗、柱子和车辆细节；选中后可直接点击其他可行动己方角色换人，再次点击已选角色或使用“取消选中”重选，保留本回合骰点。

斜视支持 100%–250% 放大。地图周围的空白处和不可点击地块支持按住鼠标左键拖动，100% 时也可平移；触屏可直接拖动，点击“全图”复位。可点击位置保留点选，拖动松手不会误执行行动。默认仍为俯视，地图编辑器和地图库保持 2D。

斜视模式使用整个浏览器视口：标题、回合、掷骰和行动说明集中在左侧栏，缩放按钮放在地图右上角。“全图”按实际可用宽高等比例居中；侧栏可收起，窄屏平板以抽屉形式展开。触屏选择落点后会自动展开行动确认；切回俯视或返回编辑会恢复原页面布局。

2D 编辑和游玩已支持四向上下桥：普通桥面不能直接连接地面，坡道箭头朝高端、反向可下桥，两侧封闭。方向可用四个按钮选择，或按 `R` 轮换；预览绿边表示地形相接，红边表示封闭。

新建地图采用新规则；含旧高架的地图须先“创建升级副本”，调整坡道，再“校验并完成升级”，原图保留。升级副本再次修改后需要重新校验，撤销/重做同时恢复相应状态。无高架的旧地图可继续游玩，也可创建升级副本。桥面已按 16 种连接绘制，前后栏杆分别排序；被遮挡的人物、动物与车辆显示彩色轮廓，选中时为金色，也可通过前景编号选择；携款和押送提示保持可见。设施内人物缩小在门口，车辆停靠入口侧边。

本版建筑和路障回到格子中央并适度降高，保留绘本细节；允许向后局部遮挡，但不把其他格子完全盖住。人物、车辆、动物及过街立杆灯缩小约 14%，山、草、水和高架桥的高度保持原样。

`5.0.y` 为测试版本，每次形成可验证的实现或修复后递增 `y`；完成整体验收后发布 `5.1.0`，后续正式修复使用 `5.1.y`。游戏版本与地图编码版本分别管理。具体阶段、规则约定和验收条件见 [5.x 斜视棋盘实施计划](docs/v5-isometric-plan.md)，实际完成情况见 [版本记录](CHANGELOG.md)。

2026-11-07：`v5.0.4` 已冻结（`98a4e30`）。当前 `5.0.5` 已实现建筑比例调整及遮挡/入口显示，用户已确认验收并授权冻结为 `v5.0.5`；后续安排为 `5.0.6` 新建 20×20 并兼容 10×10，`5.0.7` 连续行动及操作费用，`5.0.8` 集中回归，首次正式版仍为 `5.1.0`。20×20 和新行动机制尚未实现，费用和角色续行口径待确认；详见 [后续显示与玩法扩展](docs/v5-next-mechanics-plan.md)。

## Development

```bash
npm install
npm run dev
```

开发服务器默认由 Vite 提供，适合本地模块化开发与热更新。

本机系统浏览器打开 `http://localhost:4173/`。如需同一局域网的平板或其他电脑访问，使用 `npm run dev -- --host 0.0.0.0` 启动，并打开终端列出的 Network 地址；直接打开 `index.html` 无法完整运行模块和样式。

## Build

```bash
npm run build
```

构建产物输出到 `dist/`。

## Test

```bash
npm test
```

当前测试共 216 项，覆盖建筑居中与邻格可见性、真实主体遮挡/透明间隙、前景编号选择、设施入口显示，以及斜视投影与桥面点击、四向坡道表面衔接、场景排序、切换视图保留对局和触屏预览，以及 `v4/v3/v2/legacy` 地图编码、升级流程与原图保护、四向坡道寻路、实际 Worker 与同步计算一致性、旧 `localStorage` 无感升级、应用启动流程、连通山脉与草地缓冲保护、瞬移、自动上车/回库、停车场下车、待回库队列、复杂路线、逃脱和抓捕等关键移动边界。

运行 `npm run benchmark` 可测量复杂高架桥场景的首次寻路耗时。测试与结果记录见 [后续修复计划](docs/improvement-plan.md)。

## Visual study

俯视显示使用绘本素材：编辑器、俯视游戏棋盘与地图库共用连续地形和主体图片，携款、押送、角色编号及路径独立叠加。这组发布资源为 14 张 192 像素 WebP，合计约 132 KiB；原始 PNG 不进入生产构建。

斜视游戏另外使用内置 SVG 地形、桥梁、建筑和车辆，以及 4 张 384 像素人物/动物 WebP（合计约 98 KiB）。开发服务器中的 `/experiments/isometric/` 提供 50 个素材检查样例，包括遮挡轮廓与设施入口、草坪、水体、两向过街灯、所有桥面连接、四向坡道和车辆视图，不读写地图库。坐标、素材来源和朝向约定见 [斜视素材说明](docs/isometric-art.md)。

绘本棋盘样板位于 `experiments/storybook/`：运行开发服务器后打开 `/experiments/storybook/`，可查看全部 14 张主体素材、试画连续地形与斑马线、切换驾车/携款/押送/银行占位场景，并查看现有规则计算的可达格和路线。样板使用独立示例，不读写玩家地图，也不进入默认生产构建。

评估、素材范围与后续正式接入步骤见 [视觉升级方案](docs/visual-upgrade-plan.md)。文件、尺寸和生成提示见 [素材目录](experiments/storybook/assets/README.md)。
